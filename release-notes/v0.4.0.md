# Release v0.4.0

Release highlights

- Mistral AI support added for text, table, and image assessments; Mistral Small is now the default provider.
- Model-prefix routing added, with Gemini retained as an optional provider.
- Centralised, typed LLM error handling introduced with consistent HTTP statuses and retry behaviour.
- Provider 5xx and network failures now retry with exponential backoff.
- Provider raw LLM prompt and response logging is disabled by default to reduce the risk of persisting student data.
- Provider API-key, privacy, environment, and error-handling documentation updated.

## Details

### LLM providers and routing

- Added `MistralService` using `@mistralai/mistralai` for text and multimodal requests.
- Added `RoutingLLMService`, which selects a provider from the configured model name and task type.
- Supported Mistral prefixes are `mistral-small-latest`, `pixtral-`, and `open-mistral-`. Supported Gemini prefixes remain `gemini-flash-latest`, `gemini-2.5-flash`, and `gemini-2.0-flash`.
- Both `DEFAULT_TEXT_TABLE_MODEL` and `DEFAULT_IMAGE_MODEL` now default to `mistral-small-latest`.
- Model names are validated at startup and unknown prefixes fail fast with the supported prefixes listed.
- Server configuration authoritatively sets the model and reasoning effort for each request.
- Added provider-neutral reasoning effort settings. Mistral maps these to its supported `none` and `high` values; Gemini maps them according to the configured model family.
- Provider clients are initialised lazily, so only the key for a provider used by the configured models is required.

### Gemini improvements

- Gemini model selection can now be supplied by the router rather than being hardcoded in the provider.
- Added model-family-specific thinking configuration for Gemini 2.0, 2.5, and 3-series or rolling-alias models.
- Gemini and Mistral both honour `LOG_LLM_CONTENT` before logging raw provider prompts, responses, or parsed response data.

### Error handling and resilience

- Added a shared `LlmError` hierarchy under `src/common/errors/`, covering rate limits, exhausted quotas, provider server errors, authentication failures, content filtering, network failures, context limits, invalid requests, and unclassified service errors.
- Added shared provider error classification with provider-specific SDK probes for Gemini and Mistral.
- Provider errors now use stable client-facing messages; raw upstream details remain server-side in the original error and logs.
- Unrecognised provider 4xx responses map to `InvalidRequestError` with HTTP 400 rather than becoming generic HTTP 500 errors.
- `ResourceExhaustedError` now extends `HttpException` through `LlmError` and has moved to `src/common/errors/`.
- `ProviderServerError` and `NetworkError` are retryable and return HTTP 502 after retries are exhausted.

### Configuration and privacy

- Added `MISTRAL_API_KEY`, model selection, reasoning effort, and `LOG_LLM_CONTENT` environment settings.
- Provider keys are conditionally validated against the models selected at startup.
- `LOG_LLM_CONTENT` defaults to `false`; enable it only when raw LLM content is appropriate for the deployment.
- Added guidance for Mistral Zero Data Retention, Gemini service terms, provider-key handling, and production student-data safeguards.
- Documentation was audited and consolidated to remove stale guidance and align the architecture, deployment, testing, and API documentation with the implementation.

### Testing

- Added unit and E2E coverage for Mistral requests, model routing, provider configuration, shared error classes, error classification, retry behaviour, and privacy-sensitive logging.
- The unit suite passes with 510 tests across 54 test files.

## Known limitations and notes

- Mistral Zero Data Retention is not automatic. Pay-as-you-go, ZDR approval, and the separate training/improvement opt-out must be configured and verified before real student submissions are processed.
- Gemini must use the appropriate paid service and contractual configuration for student-derived data. Review the provider's current terms before production use.
- Raw LLM content is available in debug logs only when `LOG_LLM_CONTENT=true` or `1`; those logs may contain student-derived data.
- `ZodError` response behaviour is unchanged: response validation errors bypass provider mapping and continue through the existing HTTP error handling path.

## Upgrade notes

- **Default provider change:** both assessment model defaults now use `mistral-small-latest`. Set `MISTRAL_API_KEY`, or configure both model variables to recognised Gemini models and provide `GEMINI_API_KEY`.
- **New configuration:** review `.env.example` and set `DEFAULT_TEXT_TABLE_MODEL`, `DEFAULT_IMAGE_MODEL`, `TEXT_REASONING_EFFORT`, `IMAGE_REASONING_EFFORT`, and the provider key required by the selected models.
- **Breaking: upstream 5xx errors now return HTTP 502, not 500.** They are represented by `ProviderServerError` or `NetworkError` and are retried according to `LLM_MAX_RETRIES`.
- **Breaking: `ResourceExhaustedError` is now an `HttpException` via `LlmError`.** Import it from `src/common/errors/index.js`, not `src/llm/resource-exhausted.error.js`.
- **Breaking: internal LLM error-detection helpers were removed.** Code that referenced the old private helpers on `LLMService` will no longer compile.
- Run `npm ci` or `npm install` to install the new `@mistralai/mistralai` dependency.
