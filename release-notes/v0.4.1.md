# Release v0.4.1

Maintenance release focused on native ESM import hygiene, dependency maintenance,
documentation accuracy, and test-suite reliability.

## Release highlights

- Removed the configuration and LLM-error barrel modules in favour of direct imports
  from concrete modules.
- Updated LLM error-handling documentation to reflect the direct-import structure.
- Corrected the `validator` import used by image validation for NodeNext/CommonJS
  interoperability.
- Refreshed runtime and development dependencies and updated the lockfile, including
  the `multer` security override.
- Extended lint and test clean-up while preserving application behaviour.

## Details

### Import structure

- Removed `src/config/index.ts` and `src/common/errors/index.ts`.
- Migrated application code and tests to explicit `.js` imports from the relevant
  concrete modules.
- Updated error-module tests and documentation so they no longer depend on the
  deleted barrels.

### Compatibility and maintenance

- Updated image validation to use the installed `validator` CommonJS export safely
  under the project's native ESM and NodeNext configuration.
- Refreshed package metadata to version `0.4.1` and synchronised `package-lock.json`.
- Updated dependency versions and retained the repository's security-related package
  overrides.
- Applied the required lint and formatting corrections across source and test files.

### Verification

- The production build passes.
- ESLint and the British-English compliance check pass.
- The unit suite passes with 510 tests across 54 test files.
- The mocked E2E suite passes with 52 tests and one existing todo.
- `npm audit --audit-level=high` reports no vulnerabilities.

## Upgrade notes

- Run `npm ci` or `npm install` to install the refreshed dependency set.
- Internal consumers importing from `src/config/index.js` or
  `src/common/errors/index.js` must switch to the relevant concrete module.
- No environment-variable or HTTP API changes are introduced by this release.
