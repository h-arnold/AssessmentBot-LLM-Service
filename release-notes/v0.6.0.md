# Release v0.6.0

Feature release adding multi-part prompt support and upgrading the NestJS stack to v12 on Node.js 24.

## Release highlights

- Added schema-first multi-part prompt payloads with role-discriminated messages and text or image parts.
- Gemini and Mistral now map multi-part payloads to their native conversation formats.
- Upgraded NestJS from v11 to v12 together with the CLI, schematics, Swagger, throttler, Zod, dotenv, and pino tooling.
- Raised the minimum supported runtime to Node.js 24.15.0.

## Details

### Multi-part prompts

- `LlmPayload` gains a `MultiPartPromptPayload` variant whose messages carry a `system`, `user`, or `assistant` role with text and image parts.
- The variant is defined as Zod schemas in `src/llm/multi-part-prompt.schema.ts` and validated at each `send()` entry point; validation errors propagate without a retry.
- Gemini maps a leading system message to `systemInstruction` and mid-conversation system messages to user turns.
- Mistral forwards native roles with uniform content chunks and injects no instruction chunk.
- `RoutingLLMService` selects the provider using image presence.
- Legacy text and image payloads are unchanged, and the v1 assessor HTTP contract is unchanged.

### Dependency upgrades

- NestJS packages move from `^11.2.3` to `^12.1.0`, with `@nestjs/swagger` at `^12.0.2`, `@nestjs/throttler` at `^6.7.1`, and `@nestjs/config` at `^12.0.1`.
- Development tooling moves to `@nestjs/cli` `^12.0.7` and `@nestjs/schematics` `^12.0.5`.
- `zod` moves to `^4.6.5`, `dotenv` to `^18.0.4`, `nestjs-pino` to `^5.2.1`, and `@google/genai` to `^2.24.0`.
- `eslint-plugin-unicorn` moves to `^76.0.0`; the resulting lint fixes are behaviour-neutral.
- TypeScript stays at `^6.0.3` because 7.x conflicts with the current `typescript-eslint`, Nest CLI, and Swagger peer ranges.

### Contributor tooling and CI

- Node.js 24 is used consistently across CI workflows, Docker images, and documentation.
- The SonarQube workflow provisions Java 21 and upgrades `sonarqube-scan-action` to v8.
- Added an OpenCode plugin that strips `task_id` from subagent task calls so every subagent starts with a fresh context, with unit coverage.

### Verification

- The production build passes.
- ESLint and the British-English compliance check pass.
- The unit suite passes with 719 tests across 55 test files.
- The mocked E2E suite passes with 52 tests and one existing todo.

## Upgrade notes

- Node.js 22 is no longer supported; Node.js 24.15.0 or later is required.
- NestJS v12 is a framework major upgrade, so deployment configuration should be revalidated.
- The HTTP API and environment-variable contract are unchanged.
- Run `npm ci` to synchronise package metadata.
